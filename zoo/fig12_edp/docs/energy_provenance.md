# Energy-source provenance: where every component's number comes from

User question 2026-11-13: where do the component energies come from, how
was synthesis done, synthesis-only or synthesis + place-and-route?
Audited against the live energy_table.json (98 rows) and the archx tree.

## 1. Synthesized compute rows (csv_cmos: tnn_adder x5, tnn_reg x9)

The priced adders/registers (all five archs' accumulate + state rows).
- Data: `archx/src/archx/interface/csv_cmos/include/csv/tnn_adder.csv`,
  `tnn_reg.csv`: row `7,100,...` = technology 7 nm, 100 MHz,
  dynamic_uw/leakage_uw/area per instance, linear interpolation.
- Flow: **synthesis AND place-and-route**, not synthesis-only. The CSVs
  are generated by `csv_cmos_extract.py` from
  `syn_pnr_rpt/<technode>/<module>/<module>_DETAILS.rpt`, and those
  reports carry `postRoute` / `postRouteOpt` rows (verified in
  `syn_pnr_rpt/TNN7/neuron_body/neuron_body_DETAILS.rpt`: "Physical
  Design Stage ... postRoute, ... Total/Leakage/Dynamic Power,
  Wirelength"). So the power/area numbers are POST-ROUTE.
- Tool: **Cadence Genus (syn) + Innovus (P&R)** via
  https://github.com/UnaryLab/auto_syn_pnr (cloned at
  /u/yyu9/projects/auto_syn_pnr), scripts adapted from
  TILOS-AI-Institute/MacroPlacement. P&R defaults: 70% core
  utilization, square floorplan, default 400 MHz clock
  (CLK_PERIOD_NS to override).
- PDK for the 7 nm rows: **TNN7** (https://github.com/prabsy96/TNN7, a
  7 nm neuromorphic predictive PDK; auto_syn_pnr supported-nodes table
  lists ASAP7 / NanGate45 / TNN7-on-branch-prabhu). NOTE: the 7 nm
  compute rows in use today are TNN7-flavor, not ASAP7-branch runs. The
  plan already schedules replacing them with verilog_modules adder@32/
  register@32 etc. synthesized under ASAP7 proper (worklist); until
  then this is a labeled PDK-flavor caveat, same 7 nm class.

## 2. On-chip memories (cacti_fn: 36 sram rows + 4 cache rows)

NOT synthesis: analytical memory modeling via FN-CACTI
(`archx/src/archx/interface/cacti_fn/`, locally built binary) at
technology 7, FinFET, using `finfet_7nm_0p7.xml`: a synthetic
first-order scale of the validated 0.45 V device point (cacti_fn README
says replace before publication: standing footnote caveat, parent
plan). Covers every spad/spine/psum/PS-table SRAM and the L1/L2 cache
class rows (associativity-aware whole-cache model).

## 3. DRAM (cacti7: ddr4 access + IO + standing)

CACTI-7 DRAM model at 22 nm (`archx/src/archx/interface/cacti7/`),
with the run-local key fix so it genuinely models DDR4 (the shipped
template's `-dram_type`/`-iostate` keys never match the parser:
io.cc:704,737; reports verified `io_type: DDR4`: see
docs/archx_upstream_issues.md). Not synthesis: analytical.

## 4. NoC link (1 row)

First-principles 0.5*C*V^2: ASAP7 wire capacitance per um x 1 mm x 320
bits at 0.7 V (`ASAP7_global_wire_CV2` source tag). Verified by
independent re-derivation to the exact delivered value (T77 review).
Not synthesis.

## 5. NoC router (1 row): NULL placeholder

The intended source (archx csv_cmos_32nm/noc_router.csv, scaled 32->7)
has an upstream unit error (~0.2 aJ/cycle, zero leakage): row is
pending characterization; the unvalidated estimate survives only as
audit metadata. Fix path: published 7 nm router energy or auto_syn_pnr
synthesis of a router RTL.

## 6. Pending-ASAP7-synthesis rows (39 rows, join as 0 + incomplete flag)

fifo (11 rows), lif_unit (4), register_file (3), mshr_cam (2),
prefetcher (2), comparator/cmp32 (2), adder instances (2), and_gate
(2), tcam_256x16 (2), bitonic_cmp, bsf16, bsf32, psum_scan32,
popcount16, pruner, merger_tree2, l1d. Plan: RTL from
https://github.com/UnaryLab/verilog_modules (parameterized blocks with
rtl_list.tcl) plus the to-write blocks in the parent plan's worklist,
run through `bash auto_syn_pnr.sh ASAP7 <module>` = full synthesis +
place-and-route under ASAP7 (https://asap.asu.edu/), yielding the same
postRoute DETAILS reports -> csv_cmos_extract.py -> CSV rows. This is
the user/lab-side flow; when it lands, these become post-P&R ASAP7
numbers in the same pipeline as section 1.

## 7. Absent by rule

No chiplet_cmos/TSMC rows and no technology-45 rows anywhere in the
table (tech-mapping rule, enforced by energy_harvest's ValueError and
pinned by tests).
