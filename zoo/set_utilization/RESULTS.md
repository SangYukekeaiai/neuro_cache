# Static cache set utilization

Generated by `python3 zoo/set_utilization/compute.py` from the repository root, or `python3 compute.py` from this directory. No third-party packages are required.

## Inputs and interpretation

Inputs retain the B09 example [VGG16 meta.json](../../examples/input_trace/loas/vgg16_T4_n5/meta.json) and [ResNet19 meta.json](../../examples/input_trace/loas/resnet19_T4_n5/meta.json), and include every `*/*/meta.json` under the sibling `neuro_cache_bench_trace/out_real/` directory. Synthetic `out/` and `out_second/` captures are excluded. There are 176 rows: 145 real-corpus layers and 31 retained example layers. The examples are labeled `B09/examples/loas/...` and counted separately from the real corpus to avoid treating duplicate shape populations as new captures.

Shape conventions follow [LAYER_SHAPES.md](../../../neuro_cache_bench_trace/LAYER_SHAPES.md). CIN is `layers[name][2]`; COUT, kernel and stride come from `layer_params[name]`. A layer is GEMM exactly when listed in `meta.gemm`: KH = KW = 1, CIN = K, COUT = N (checked against the stored shape and parameters). Other layers are Conv, including 1×1 convs. All captured layers are included; stride and token count do not change weight-line placement. The corpus path is required at regeneration time.

[Geometry](../../examples/cache/base.json): CIN block 16, COUT block 4, 1 byte(s) per weight, 64-byte lines. Channel blocks round up, including partial blocks.

**Core assignment assumption:** 16 cores; core c owns COUT blocks `[c*b, min((c+1)*b, n_cout_blocks))`, where `b = ceil(n_cout_blocks/16)`. Each core accesses every CIN block and kernel position for its own COUT slice. Min/mean include all 16 cores (an empty core contributes zero). Global reach is the union across all layer lines. For L2, per-core reach is each core's contribution to the shared cache.

`split` means the current [khkw_split.cpp](../../src/lays/cachesim/native/src/layout/khkw_split.cpp): `line = (pos//q)*(n_cout_blocks*n_cin_blocks*q) + cout_blk*(n_cin_blocks*q) + cin_blk*q + pos%q`, with `q = min(8, KH*KW)`. `concat` means the [proposed cin_khkw_concat](../../docs/plans/2026-11-04-cin-khkw-concat-layout-plan.md): `D = n_cin_blocks*KH*KW`, `line = cout_blk*D + cin_blk*KH*KW + pos`. Both use `pos = kh*KW + kw` and `set = line % num_sets`.

Reach columns report the percentage of all sets reached. Imbalance is `max(lines in a set) / (total valid lines / num_sets)` globally, including unreached sets in the denominator; 1.000 is perfectly balanced. Lines counts distinct valid weight blocks, not the split layout's address span or unused ragged-position slots. `bound` flags a layer with fewer lines than the level's line capacity, so that layer cannot fill the level under either policy. The ratio is identical for both layouts.

These are static reachability and distribution measurements, not measured occupancy or hit rates. Reaching every set does not imply filling every way. Per-core L1 residency is further limited by the size of that core's own slice; the global capacity comparison is only a necessary bound.

For concat, a core's contiguous COUT slice gives a contiguous interval of `owned_cout_blocks*D` lines: it reaches all sets exactly when that interval has at least `num_sets` lines. `D < num_sets` alone therefore does not imply a reachability loss.

On 3×3 layers the split layout's eight low-position residues plus the ninth position bias some sets even when reach is 100%; concat removes the ragged gaps and spreads consecutive valid lines with counts differing by at most one. A full-set reach or improved balance alone does not establish a runtime or hit-rate improvement.
