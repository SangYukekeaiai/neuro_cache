The denominator changed

A weight-address event is a physical burst. Elements are still expanded to find which cache-line tags the burst touches, but consecutive identical tags inside that event collapse to one cache access.

Precise rule. For each event, expand its weights only to form cache-line tags. Collapse consecutive duplicate tags within that event, then replay the remaining distinct-line sequence. Never deduplicate across event boundaries.
Evidence: log/2026-07-28-debug-pipeline-plan.md, tiny worked example and the corrected loop in profiling/0726/native/cache_sweep.cpp.

What occupies one cache line?

The two replay layouts keep the same LoAS burst width of 16 COUT weights. They differ in how extra line capacity is used when the line is wider than one burst.

Baseline layout

COUT only

Keep one fixed CIN and extend farther along COUT. Larger lines absorb more consecutive output-channel weights from that same input channel.

At 16 B the layouts are identical. Their behavior diverges at 32 B and 64 B: COUT-only extends one channel horizontally, while CIN × COUT packs two or four adjacent input channels into the same line.
