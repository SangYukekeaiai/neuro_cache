## Step 1: benchmark layer-dimension inventory and generator-coverage check

Goal: know every layer dimension in the 8 benchmarks, and check that the five
weight-trace generators (loas, ptb, spinalflow, prosperity, gustavsnn) cover
every case: before any generation runs.

### 1a. Ground truth already exists: verify it, don't rebuild it

`/u/yyu9/neuro_cache_bench_trace/LAYER_SHAPES.md` (generated by
`catalog_layer_shapes.py` from each capture's `meta.json`) already tables every
captured layer of all 8 benchmarks: type (spiking-Conv vs spiking-GEMM),
kh/kw, oc/inc, ho/wo, T, hin/win, stride, padding, dilation, groups, and
M/K/N for GEMMs. Totals: A02 12 layers, A04 16, A07 72, A08 13, B09-vgg16 13,
B09-resnet19 19, C01 6+6 = **157 captured layers**.

Tasks:
1. Regenerate it (`conda run -n base .venv/bin/python -I
   catalog_layer_shapes.py --metadata-only`) and diff against the committed
   copy: confirms it matches the current captures after today's pulls.
2. Copy (or link) the result into `zoo/wt500_fig3cfg/` as
   `layer_shapes.md` so the campaign folder is self-contained; stamp the
   source commit of neuro_cache_bench_trace.

### 1b. Extract the distinct dimension cases

From the 157 layers, produce a small table of **unique shape classes** the
generators must handle, e.g.:
- conv: (kh,kw) ∈ {1x1, 3x3}, stride ∈ {1,2}, padding ∈ {0,1}, groups=1
- gemm: as 1x1 conv with wo=1 (incl. A07's 72 transformer GEMMs, large K)
- extremes: max/min of inc, oc, ho*wo, T (e.g. T=32 for A08, T=16/10 for C01,
  the 131,072-tile SpinalFlow C01 heavy case)

Deliverable: `zoo/wt500_fig3cfg/layer_dim_coverage.md`: one table of unique
cases, one row per case, with the benchmark layers that exhibit it.

### 1c. Check generator coverage against those cases

For each of the 5 generators, answer per shape class: covered / excluded (and
why) / unknown. Two evidence sources, cross-checked:
1. **Solve-stage manifest** (`zoo/wt500_fig3cfg/outputs/manifest.json`, on
   DeltaAI): 755 valid (arch, layer) pairs, 30 excluded, 17 prosperity
   INFEASIBLE. Map every exclusion/infeasible back to a shape class: do the
   30 exclusions correspond to dimension limits of a generator, or to loader
   policy (`build_workload_from_trace` skips non-3x3/stride-1 convs via
   `exclusion_reason`)?
2. **Generator code**: dimension assumptions in each
   `src/lays/weight_trace_gen/*/``*Gen.h` + `native_bridge.py` (e.g. PTB
   TW_SIZE 8x8, prosperity per-CIN tiling, gustavsnn wave width = per-schedule
   NodeLevel spatial product: never flat 4).

Deliverable: coverage matrix (5 archs x shape classes) appended to
`layer_dim_coverage.md`, with every "not covered" row carrying the reason and
whether it is expected (recorded outcome) or a gap to fix.

### Step 1 exit criteria

- Regenerated LAYER_SHAPES matches committed copy (or diffs explained).
- Every one of the 157 layers appears in exactly one shape class.
- Every (arch, layer) exclusion in the manifest is explained by a shape class
  or a recorded policy; zero unexplained gaps.
- User signs off on the coverage matrix.
