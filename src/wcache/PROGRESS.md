# wcache rebuild: progress board

Authority: `log/2026-08-17-wcache-event-driven-plan-v3.md`. Unit names and exit
criteria come from its Part 7; the V-list is its Part 7 verification table.

v3 (2026-08-17) supersedes the v2 plan and adds two mechanisms: C1, the core
handles one burst at a time on a self-timed schedule (4.5, N14), and C2, an L1-side
prefetcher that fetches burst k+1 early while leaving the PE unchanged (4.6, N15,
N16). Nothing already built is invalidated: A1 stands, A2 is untouched, A3 gains a
query surface, B3 gains the demand bit and the reserve, C3 grows, and C5 is new.

Pipeline: implementer builds one function/class/struct, stops, writes
`EXPLAIN.md`. User reviews. On "next", the reviewer writes tests for what was
just built and the implementer starts the following increment.

**Amended 2026-08-18 by B73 and B74, both explicit user answers.** The
per-unit handshake is **lifted**: the implementer no longer stops for a "next"
between units, and units run in batches (A4c+A5, then all of B, then all of C),
with a commit still per unit inside each batch. Detail-level design decisions
are delegated to the coordinator; the human reviews asynchronously from the repo
record and flags what they dislike. What is **not** amended: `EXPLAIN.md` and
this board keep their full depth (B57), which is the condition that makes the
delegation safe.

`EXPLAIN.md` is erasable: it is overwritten at every increment and is never the
record of anything. This board is the record.

`CPP_NOTES.md` is the standing reference for the C++ features the code uses,
written for a C background. It is durable, not erasable, and each unit appends
the features it introduces (its section 17 lists what is still owed).

A4c's shape is five small bodies over one private helper. `base_slot(line)`
returns the set's lowest slot, so a set is exactly `[base, base +
